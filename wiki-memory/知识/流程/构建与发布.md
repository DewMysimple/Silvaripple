# 构建与发布

## 本地构建

- PyInstaller 生成 console 模式的单文件 Python sidecar；console 由 Tauri 以无窗口标志启动，仅用于标准输入输出 RPC。
- Tauri 使用 `--no-bundle` 将 React/Vite 生产资源嵌入主程序；同包分发冻结后端和离线运行时，不再生成本地安装器。
- PyInstaller 和交付 staging 位于系统临时目录；前端构建与 Rust 缓存分别位于 `frontend/dist` 和 `frontend/src-tauri/target`。
- ZIP 捆绑主程序、Python sidecar、silk-wasm、Node、FFmpeg 和许可证。
- Node 与 FFmpeg 的版本、文件大小和 SHA-256 由运行时锁约束；二进制不进入 Git。
- 构建先进入 staging，自检通过后才替换固定目标。
- `Build-TauriSidecar.ps1` 负责冻结后端；`Build-Portable.ps1` 负责桌面构建、共用资源映射、包内逐文件构建清单、ZIP 重新解压和隔离自检。公共校验位于 `Delivery.Common.ps1`。
- 正式构建与发布 PowerShell 脚本保持 ASCII，以兼容 Windows PowerShell 5。
- `Publish-Local.ps1` 要求干净工作区，根 `dist/` 只保留 `ChatWechat.zip` 与同包解压的 `ChatWechat/`。普通异常整组回滚，不承诺掉电原子性。
- 替换前按旧构建清单检查全部应用文件与目录，遇到未知文件、嵌套空目录、文件系统链接或不可信清单即停止，避免清除用户内容。
- 自检须确认文件清单、冻结服务初始化、隔离用户配置、不同工作目录与精简 PATH，且 Node/FFmpeg 来自包内并能实际执行；进程运行有超时、退出码与输出管道检查。正式交付还要实际启动 `dist/ChatWechat/ChatWechat.exe` 并验证退出。
- 应用配置和历史留在当前用户应用数据目录，不能进入应用包。

## GitHub 发布

- 日常 `main` 推送只保存源码。
- 用户明确要求发布时才更新语义版本并推送版本标签。
- 标签工作流构建版本化 Windows 应用 ZIP 和 SHA-256 文件，不生成源码 ZIP；GitHub 仓库本身是源码来源。
- 标签必须与项目唯一版本源一致；锁定 FFmpeg 归档变量缺失或校验不符时停止发布。
- 旧 Release 保留。
