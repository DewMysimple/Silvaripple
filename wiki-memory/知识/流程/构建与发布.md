# 构建与发布

## 本地构建

- PyInstaller 使用 onedir/windowed 模式，onedir 仅作为 NSIS 安装包的内部 staging。
- 所有中间文件位于仓库外的临时目录。
- 安装包 staging 捆绑网页资源、silk-wasm、Node、FFmpeg 和许可证。
- Node 与 FFmpeg 的版本、文件大小和 SHA-256 由运行时锁约束；二进制不进入 Git。
- 构建先进入 staging，自检通过后才替换固定目标。
- `Build-Installer.ps1` 负责 staging、NSIS 编译和隔离安装/卸载自检。
- `Publish-Local.ps1` 要求干净工作区并原子替换工程内 `artifacts/发布版本/` 的安装包、校验文件，同时通过同一 NSIS 测试安装器更新 `artifacts/安装版/ChatWechat/`；这些目录被 Git 忽略。
- 冻结和安装后自检必须确认服务可初始化，且 Node 与 FFmpeg 来自安装包而不是系统 PATH。
- NSIS 编译器版本由 `packaging/installer.lock.json` 约束；缺失时只在临时目录下载，不进入 Git。

## GitHub 发布

- 日常 `main` 推送只保存源码。
- 用户明确要求发布时才更新语义版本并推送版本标签。
- 标签工作流构建版本化 Windows NSIS 安装包和 SHA-256 文件，不生成源码 ZIP；GitHub 仓库本身是源码来源。
- 标签必须与项目唯一版本源一致；锁定 FFmpeg 归档变量缺失或校验不符时停止发布。
- 旧 Release 保留。
