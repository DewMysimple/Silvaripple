# 开发、验证与提交

每个逻辑任务遵循：读取记忆 → 修改 → Python/React/Rust 测试、格式与类型检查 → 前端生产构建和浏览器回归 → 记忆同步与体检 → 提交 → 由干净 `HEAD` 执行 ZIP 本地发布和解压应用自检 → 推送。

如果打包或自检失败，保留上一版外部产物，不推送失败状态。远端前进或推送冲突时停止，不执行强推。

基础命令：

```text
scripts/Invoke-QualityGate.ps1
scripts/Build-Portable.ps1
scripts/Publish-Local.ps1
```

前端命令必须使用项目锁定的 pnpm 版本。Rust 命令使用 `frontend/src-tauri/Cargo.toml`。
正式本地发布以已提交的 `HEAD` 构建应用 ZIP，因此工作区存在未提交修改时发布脚本应拒绝执行。开发预验证可先运行 `Build-Portable.ps1`，但其产物不能冒充最终干净提交。

浏览器回归使用开发服务器的合成数据，覆盖跨页面交互和多尺寸、深色、大字体。生产前端没有 Mock 后备，必须另外验证解压后的实际桌面主程序启动与正常退出；冻结后端自检不能代替桌面验证。
