# 2026-08-24｜正式安装版构建体系

- 目标：把用户交付从免安装目录改为当前用户 NSIS 安装包，同时保持 Python、React、pywebview 的可维护架构。
- 决策：PyInstaller onedir 只在仓库外临时 staging 中生成；正式交付固定为 `ChatWechat-Setup.exe`、源码 ZIP 和 SHA-256 清单。
- 决策：安装到 `%LOCALAPPDATA%/Programs/ChatWechat`，用户数据继续位于 `%LOCALAPPDATA%/ChatWechat`；升级覆盖程序文件但不触碰设置、密钥、历史或导出归档。
- 决策：安装器使用当前用户权限，创建开始菜单与桌面快捷方式；首次安装尝试将旧便携目录重命名为带时间戳的备份，不删除旧目录。
- 决策：首版不签名；普通 `main` 推送不创建 GitHub Release，只有明确版本标签才发布安装包。

## 文件变更

- 新增 `packaging/ChatWechat.nsi`、`packaging/ChatWechat.ico`、`packaging/installer.lock.json`。
- 新增 `scripts/Build-AppStaging.ps1` 和 `scripts/Build-Installer.ps1`；`scripts/Publish-Local.ps1` 改为原子覆盖安装包、源码包和校验文件。
- Release 工作流改为构建 NSIS 安装包；移除用户交付用的 portable 说明。
- 版本、Node、FFmpeg 和 NSIS 仍通过锁定文件与 `pyproject.toml` 约束。

## 验证

- Python 78 项测试、React 5 项测试、TypeScript 类型检查和 Vite 生产构建通过。
- NSIS 3.11 真实编译成功；隔离安装、自检、卸载均通过，安装后冻结态自检确认 WebView2、CNG、DPAPI、Node、FFmpeg 和服务初始化可用。
- 构建失败不会替换桌面固定产物；用户微信数据库、WAL、SHM 不由安装器访问或修改。

## 遗留事项

- 首版没有代码签名证书，Windows 可能显示未签名发布者。
- GitHub Release 仍需用户明确提出发布要求，并准备与运行时锁一致的 FFmpeg 归档变量。
