# 2026-09-16｜Tauri 架构与多账号数据发现

## 目标

将桌面壳迁移到 React、Vite 和 Tauri，保留经过验证的 Python 微信读取核心；移除对单台开发机器路径的依赖，并把多账号切换和首次数据定位做成可交付的产品流程。

## 决策

- 采用 [[决策/ADR-008-Tauri桌面壳与Python-Sidecar|Tauri 桌面壳与 Python sidecar]]。
- 采用 [[决策/ADR-009-微信数据发现与账号上下文隔离|微信数据发现与账号上下文隔离]]。
- Tauri 使用官方命令 IPC 和目录对话框；Python Bridge 继续保持兼容信封。
- 旧 pywebview、Python 内嵌网页资源、自维护 NSIS 脚本和 onedir staging 退出生产链路。

## 变更

- 新增 `frontend/src-tauri/` Rust 壳、能力配置、Tauri 配置和 Cargo 锁文件。
- 新增 `chatwechat/sidecar.py`，并把源码入口改为 Tauri 开发启动器/sidecar 命令分发器。
- 前端 Bridge 改用 Tauri invoke 和原生目录选择器；新增首次连接、数据候选、全局账号切换和账号页面重置。
- 后端新增注册表、Known Folder、OneDrive、AppData、用户目录与标准磁盘位置的有限发现，并支持经校验的手动目录归一化。
- 任务历史和运行中操作增加账号上下文；账号切换时清理旧账号页面状态。
- 构建链改为 PyInstaller 单文件 sidecar + Tauri NSIS，质量门新增 Rust 格式、测试和检查。
- 删除 Python 包内生成的网页资产、pywebview 依赖和旧自维护安装器脚本。

## 验证

- Python 回归测试通过，新增数据根归一化、候选去重、注册表提示、sidecar 状态复用和账号历史隔离覆盖。
- React 测试、TypeScript 类型检查和 Vite 生产构建通过。
- Cargo 格式检查、测试和检查通过。
- Tauri 开发窗口成功启动并拉起 Python RPC sidecar。
- 冻结 sidecar 自检通过，Tauri 成功生成 NSIS 安装包；安装后 Node 与 FFmpeg 从捆绑资源解析。
- 发布态 sidecar 以安装资源目录而非编译机源码目录作为工作目录；隔离安装、自检和卸载均已通过。
- 数据根切换会关闭旧仓库，前端异步预览与统计响应会核对账号上下文，避免快速切换时旧账号结果回写。

## 结果

桌面 UI 和窗口生命周期已切换到 Tauri，微信高风险数据能力保持在原 Python 服务内。首次使用和多账号场景不再依赖开发机器路径，用户能在自动候选与经验证的手动选择之间完成数据连接。

- 代码签名证书仍未提供。
- Python 服务门面和部分 React 页面仍偏大，后续继续在稳定 RPC 合约内拆分。
