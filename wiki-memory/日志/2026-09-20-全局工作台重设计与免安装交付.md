# 全局工作台重设计与免安装交付

## 目标与决策

用户要求系统性优化全局功能、排版与信息层级，同时拆分公共模块和文件夹结构；本地交付改为根 `dist/` 中的应用 ZIP 与对应解压目录，直接运行解压应用验收。该明确要求取代原安装器与工程内安装实例策略。

## 变更

- React 外壳只保留启动、主题和页面装配；七个功能模块位于 `frontend/src/features/`，页面通过子组件、动作 hook 和纯规则模型组织。
- 公共 `ui/layout`、`ui/primitives` 与确认弹窗统一面板、页面标题、状态、表单行、类型筛选、进度及错误交互；字体使用统一 token 与 rem，保留明暗主题和密度。
- 首页突出账号状态、下一步和数据概览；导出分为范围、内容、保存位置、检查栏，高级选项按需展开；设置按五类显示单一面板；搜索、媒体与任务使用一致布局。
- Zustand 按账号/会话/操作拆分；上下文代次防止账号 ABA 和换根后旧请求回写；选择详情快照不再随列表过滤丢失。会话支持继续加载、独立读取状态，重复加载和旧预览不会污染当前会话。
- 失败或同根数据发现不再使运行中任务失去跟踪；导出估算、重复提交、搜索整天日期边界、取消与错误反馈均有行为回归。
- 开发 Mock 与生产 Bridge 分离；生产构建不提供示例数据兜底。开发浏览器测试使用合成数据，不访问真实聊天。
- `Build-Portable.ps1` 组装 Tauri EXE、Python sidecar、锁定运行时、许可证和构建清单；ZIP 重新解压后校验，自检使用隔离配置、不同 cwd 和精简 PATH。
- `Publish-Local.ps1` 以普通异常可回滚的方式整组替换 `dist/ChatWechat.zip` 与 `dist/ChatWechat/`；未知用户文件不自动覆盖。不是掉电原子交换。
- Windows Job Object 管理后端进程树，RPC 阻塞或锁占用不再阻塞窗口退出，有限等待后终止后端及其后代。
- 开启 TypeScript 未用符号检查，统一 Prettier 格式检查，新增 Playwright 多页面和多窗口尺寸回归并接入质量门。
- 清理旧交付布局与重复构建缓存：移至工程外临时备份，不删除用户文件；交付目录只由新发布脚本维护。

## 验证

- 统一质量门通过：Python 106 项、React 58 项、浏览器 6 项、Rust 4 项；类型、格式、生产构建和记忆体检通过。旧 Python 测试不再锁死页面中文文案、CSS 字符串或组件所在文件，UI 行为由 React 与浏览器测试覆盖。
- 浏览器覆盖会话选择、筛选后导出、搜索跳转、媒体检查及七个页面的 1080/1440/1920 宽度；覆盖深色加大字体。
- Rust 真实系统进程测试覆盖正常关闭、无响应关闭、RPC 持锁与后代回收。
- 预构建 ZIP 重新解压后，冻结后端及包内 Node/FFmpeg 在隔离用户目录、精简 PATH、不同工作目录下实际执行成功。真实桌面 EXE 已正常渲染首次连接引导，不借用开发服务器或 Mock。
- 正式交付仍由最终干净提交运行同一质量门和发布脚本，保证包内构建清单与源码提交对应。

## 遗留与边界

- 微信解析核心与只读安全边界保持原协议，未以本次 UI 改造声明支持更多微信版本。
- Windows 仍需 WebView2；代码签名证书尚未提供。
- Python 大型服务门面继续按用例渐进拆分；本轮重点解决前端大页面、状态与交付脚本。
