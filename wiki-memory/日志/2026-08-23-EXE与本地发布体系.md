# 2026-08-23｜EXE 与本地发布体系

- 目标：建立可维护、可验证、不会破坏上一版的 Windows EXE 与本地固定产物流程。
- 状态：完成。
- 日志索引：[[日志/MOC_工作日志|工作日志 MOC]]

## 已确认的决策

- 继续使用 Python、React 和 pywebview 的 onedir/windowed 桌面架构。
- PyInstaller 配置只使用仓库相对路径；所有构建中间文件位于仓库外。
- Node 与 FFmpeg 只复制经过版本、大小和 SHA-256 验证的文件，不提交二进制。
- 本地发布只接受干净工作区，先完成隔离自检，再原子替换固定源码包和便携目录。
- 普通源码推送不创建 Release；标签工作流只由明确版本标签触发。

## 文件变更

- 新增可维护 PyInstaller spec、运行时锁和便携版说明。
- 新增统一质量门、便携构建和本地原子发布脚本。
- 新增仅标签触发的 Windows Release 工作流。
- 自检增加服务初始化和捆绑运行时来源验证；WebView2 缺失时显示可读提示。
- 增加打包配置、发布触发和版本唯一来源测试。

## 测试与验证

- Python 78 项测试通过，React 5 项测试通过，TypeScript 类型检查通过。
- PyInstaller 真实构建成功；冻结态隔离自检全部通过。
- 自检确认 Node 与 FFmpeg 均来自便携目录。
- 产物扫描未发现仓库构建路径或本机微信数据路径。

## 结果、问题与下一步

- 结果：源码、冻结 EXE 与管理员助手共用同一入口，便携版无需系统 Node 或 FFmpeg。
- 已知限制：未配置代码签名证书；标签发布前需要提供与运行时锁一致的 FFmpeg 归档变量。
- 下一步：后续每项逻辑任务复用该质量门与本地发布流程。
