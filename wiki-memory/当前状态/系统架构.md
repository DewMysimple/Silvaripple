# 系统架构

## 架构概览

项目采用 Windows 模块化桌面单体：React 静态前端通过 pywebview 注入的类型化 Bridge 调用 Python 应用服务；应用服务协调只读快照、数据库解析、媒体恢复、导出和任务持久化。

## 模块关系

| 模块 | 职责 | 主要依赖 |
| --- | --- | --- |
| Desktop | 启动窗口、Bridge、冻结资源、提权子模式 | pywebview、Application |
| Application | 账号、会话、导出、搜索、统计和任务用例 | Domain、Infrastructure |
| Domain | 模型、状态、错误和业务规则 | Python 标准库 |
| Infrastructure | WCDB、CNG、DPAPI、WAL、文件、网络和配置 | Windows、cryptography |
| Export/Media | 渲染、原子归档、本地及腾讯媒体恢复 | Domain、Infrastructure |
| Frontend | 工作台页面、状态和交互 | React、Zustand、Bridge |

## 数据流

微信源文件 → 一致性只读快照 → 按页 HMAC/AES 解密 → schema 探测与标准化 → 内存预览/统计或临时导出目录 → 原子提交到用户输出目录。

## 运行与发布

- 开发态由 Python 直接加载 `chatwechat/web`。
- 生产态使用 PyInstaller onedir 作为内部 staging，NSIS 安装包将其安装到当前用户的程序目录。
- 用户程序位于 `%LOCALAPPDATA%/Programs/ChatWechat`，设置和运行数据继续位于 `%LOCALAPPDATA%/ChatWechat`。
- 本地 NSIS 安装包和 SHA-256 文件位于仓库内被忽略的 `artifacts/发布版本/` 并原子覆盖；同一构建还更新 `artifacts/安装版/ChatWechat/` 作为工程内安装实例；不再生成源码 ZIP 或便携交付目录。
